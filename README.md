# Формируем авансовые отчёты из документов (PDF/изображения)

Конвейер автоматической обработки билетов: **документы (PDF/изображения) → распознавание (LLM) → авансовые отчёты в 1С → Excel-сводка → письмо-уведомление**.

## Что делает


1. читает новые файлы (`read_pdf.py`): PDF — текстовый слой (с OCR-фолбэком), изображения (PNG/JPG/…) — через OCR;
2. распознаёт их через LLM (`recognize.py`) → структурированные данные;
3. пишет авансовые отчёты в 1С через интерфейс OData (`write_1c.py`) — документ, строки «Прочее», вложения;
4. формирует отчет в Excel (`make_excel.py`) в указанный каталог;
5. отправляет письмо-сводку (`send_mail.py`): созданные документы (со ссылками в 1С), не найденные в справочнике физлица, а также вложение Excel.

Повторные запуски на той же папке безопасны: обработанные файлы запоминаются в реестре `registry.json`, дублей в 1С не будет.

## Требования

- Windows 10/11 (на Linux/macOS — через `run.sh`, нужен bash);
- Python 3.12 (рекомендуется именно 3.12: под более новые версии, например 3.15, часть OCR-библиотек ещё не собрана);
- доступ к 1С по OData. 
   В разделе [Администрирование → "Синхронизация Данных" → Настройки стандартного интерфейса OData]
   - Создайте отдельного пользователя
   - Опубликуйте метаданные:
      1. Документ.АвансовыеОтчеты
      2. Справочник.АвансовыеОтчеты_ПрисоединенныеФайлы
      3. Справочник.ФизическиеЛица
      4. РегистрСведений.ПрисоединенныеФайлы
- ключ LLM API

## Установка (Windows)

1. **Установите Python 3.12** с [python.org](https://www.python.org/downloads/). На первом экране установщика отметьте **«Add Python to PATH»**.

2. **Скопируйте папку проекта** на рабочий компьютер (целиком, включая `src/`, `config/`, `requirements.txt`).

3. **Установите библиотеки** — откройте cmd в папке проекта и выполните:
   ```
   py -3.12 -m pip install -r requirements.txt
   ```
   `py -3.12` — встроенный лаунчер Windows, он всегда запускает именно Python 3.12, даже если в PATH есть другая версия.

## Настройка (переменные окружения)

Секреты задаются **переменными окружения**. Если переменная не задана, скрипт берёт значение из локального конфига в `config/` (фолбэк — читает модуль `src/config_reader.py`).

| Переменная | Что это |
|---|---|
| `ONE_S_BASE_ID` | номер базы 1С:Фреш (подставляется в URL из конфига) |
| `ONE_S_LOGIN` | логин OData |
| `ONE_S_PASSWD` | пароль OData |
| `LLM_URL` | базовый URL LLM API |
| `LLM_API_KEY` | ключ API DeepSeek |
| `MAIL_HOST` | SMTP-сервер (по умолчанию `smtp.yandex.ru`) |
| `MAIL_PORT` | порт SMTP (по умолчанию `465`) |
| `MAIL_LOGIN` | ящик-отправитель (Яндекс) |
| `MAIL_PASSWD` | пароль приложения Яндекс |
| `MAIL_TO` | получатель письма |

Windows (cmd):
```
setx ONE_S_BASE_ID "2334476"
setx ONE_S_LOGIN "логин"
setx ONE_S_PASSWD "пароль"
setx LLM_URL "https://api.deepseek.com"
setx LLM_API_KEY "ключ"
setx MAIL_LOGIN "ваш_ящик@yandex.ru"
setx MAIL_PASSWD "пароль_приложения"
setx MAIL_TO "кому@example.com"
```

Linux/macOS/WSL (bash):
```
export ONE_S_BASE_ID="2334476"
export ONE_S_LOGIN="логин"
export ONE_S_PASSWD="пароль"
export LLM_URL="https://api.deepseek.com"
export LLM_API_KEY="ключ"
export MAIL_LOGIN="ваш_ящик@yandex.ru"
export MAIL_PASSWD="пароль_приложения"
export MAIL_TO="кому@example.com"
```

> После `setx` перезапустите консоль (или откройте новую), чтобы переменные подхватились.

### Файл настроек config/properties.json

Все настройки собраны в **один файл** `config/properties.json` с разделами:

- `one_s` — `base_url` (полный URL базы, включая путь), `login`, `password`;
- `llm` — `base_url`, `api_key`, `model`;
- `mail` — `host`, `port`, `login`, `password`, `to`;
- `advance_reports` — GUID-ы для авансовых отчётов (несекретные);
- `components` — какие необязательные компоненты включены.

Переменные окружения (см. таблицу выше) имеют приоритет над этим файлом. Полный адрес базы (включая путь) хранится в `properties.json` → `one_s.base_url`: в коде путь не захардкожен.

В репозитории лежит только **шаблон** `config/properties.example.json` (с плейсхолдерами). Скопируйте и заполните реальными значениями:

```
copy config\properties.example.json config\properties.json
```

Файл `config/properties.json` с реальными значениями — в `.gitignore` и в репозиторий не попадает.

### Компоненты

В `properties.json` → `components` указываются необязательные компоненты (ключи совпадают с именами скриптов):

- `make_excel` — формирование Excel-сводки;
- `send_mail` — отправка письма-уведомления.

Если компонент равен `false` или отсутствует — он не выполняется. Управление происходит через `src/component_manager.py`.

### Список мероприятий (events.json)

Известные мероприятия перечислены в `config/events.json` (простой массив):

```json
["ЧМ горы", "КД", "КМ пеш", "ПМ горы", "ЧМ вода", "ПР"]
```

Скрипт находит мероприятие по имени файла (поиск по целым словам). Если ни одно мероприятие не найдено — файл группируется в отдельный авансовый отчёт с назначением **«Нераспознано»**.

В репозитории лежит шаблон `config/events.example.json`.

### Почта (Яндекс)

Если для отправки сообщений используется Яндекс-почта, то нужно в аккаунте Яндекса выполнить следующие настройки:
1. Установить **пароль приложения** (не основной пароль ящика). 
Создайте его в [Яндекс ID → Безопасность → Пароли приложений](https://id.yandex.ru/security/app-passwords) и укажите в `MAIL_PASSWD` (или в `properties.json` → `mail.password`).
2. В настройках почты необходимо разрешить доступ к почтовому ящику с помощью почтовых клиентов:
[Почта → Настройки → Все настройки → Почтовые программы]

### Несекретные настройки

- `properties.json` → `advance_reports` — **обязательный** раздел: GUID-ы из вашей 1С (организация, подотчётное лицо, счёт 26, субконто, номенклатура, валюта, вид операции). Заполните его из шаблона `properties.example.json`.
- модель LLM — по умолчанию `deepseek-flash` (можно переопределить в `properties.json` → `llm.model`).

Если вы продолжаете обработку на той же базе — скопируйте также `registry.json` (реестр обработанных файлов), иначе скрипт создаст дубли документов в 1С.

## Запуск

```
run.cmd --from "C:\путь\к\билетам" --out "C:\путь\к\результату"
run.cmd --from "C:\путь\к\билетам" --out "C:\путь\к\результату" --dry-run
```

Для bash (WSL / Git Bash / Linux / macOS):
```
./run.sh --from "/путь/к/билетам" --out "/путь/к/результату"
```

- `--from` — папка с документами: PDF и изображения (PNG/JPG/…);
- `--out` — куда сохранять результат (Excel);
- `--dry-run` — только показать план, без записи в 1С и без отправки письма.

## Результат работы

После успешного прогона вы получаете:

- **Excel-сводку** — `<out>/uploaded_tickets_<дата>_<время>.xlsx`;
- **письмо-уведомление** на `MAIL_TO`: созданные документы (кликабельные ссылки в 1С), не найденные в справочнике физлица и вложение Excel;
- **лог** — `log/run_<дата>.log` (один файл на день, каждая строка с меткой времени до миллисекунд).

## Примечания

- **OCR**: если PDF — скан или битый шрифт, текст извлекается через RapidOCR (ставится из `requirements.txt`). Изображения (PNG/JPG/…) всегда распознаются через OCR.
- **SSL**: если в сети есть корпоративный прокси с самоподписанным сертификатом, вызов DeepSeek настроен с `verify=False` (см. `src/recognize.py`).
- **Распознавание** — формат-независимое: LLM распознаёт любой проездной документ по структуре (пассажир + номер билета + маршрут + сумма), без жёсткого списка перевозчиков. Вид транспорта (`air`/`rail`/`bus`) определяется автоматически.
- **Возврат прихода** («Возврат прихода»): сумма возврата вычитается из суммы билета (в разрезе номеров билетов), входящим документом указывается чек возврата.
